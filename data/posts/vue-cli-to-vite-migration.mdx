# Vue CLI → Vite 6 마이그레이션

골프존 앱 혜택존 웹뷰 프로젝트(benefit-zone)는 `vue-cli-service`(webpack 5) 기반으로 빌드되고 있었습니다. 개발 서버 기동·HMR이 느리고, 코드 스플리팅 없이 단일 `app.js`로 배포되는 문제가 있어 **Vite 6**으로 빌드 시스템을 이관했습니다.

이 글은 마이그레이션 전체 과정과, 이관 전(master)·후(develop) 브랜치에서 각각 빌드를 실행해 비교한 성능 지표를 정리합니다.

## 이관 전 상태

| 항목   | 내용                                                               |
| ------ | ------------------------------------------------------------------ |
| 빌드   | `@vue/cli-service` 5.x (webpack 5)                                 |
| 런타임 | Vue `3.2.13` + Pinia + Vue Router 4 + TanStack Query               |
| 스타일 | `sass@1.32` + `sass-loader` (legacy API)                           |
| Node   | 22.14.0                                                            |
| 산출물 | `app.js` + `chunk-vendors.js` 2개 (엔트리 2.74 MiB, 스플리팅 없음) |

webpack 빌드 로그에도 이미 경고가 떠 있었습니다.

```
webpack performance recommendations:
You can limit the size of your bundles by using import() or require.ensure
to lazy load some parts of your application.
```

## Vite 버전 선택

기존 의존성을 최대한 유지하는 조건으로 버전을 비교했습니다.

| 항목      | Vite 5.4                            | Vite 6                             | Vite 7/8                      |
| --------- | ----------------------------------- | ---------------------------------- | ----------------------------- |
| `vue@3.2` | OK                                  | OK                                 | OK                            |
| Sass API  | legacy 기본 → `sass@1.32` 유지 가능 | modern 기본 → sass 업그레이드 권장 | legacy 제거 → 업그레이드 필수 |
| Node 요구 | 18+                                 | 18.18+ / 20 / 22                   | 20.19+ / 22.12+               |

런타임 의존성(`vue`, `pinia`, `vue-router`, `swiper` 등)은 어느 버전이든 그대로 쓸 수 있어, Node 22 환경에서 무리 없이 올릴 수 있는 **Vite 6**을 선택했습니다. Sass는 이관하는 김에 `sass@1.89` + `sass-embedded`로 올리고 modern-compiler API를 적용했습니다.

## 마이그레이션 과정

### 1. 의존성 교체

```diff
  "scripts": {
-   "serve": "vue-cli-service serve",
-   "build": "vue-cli-service build",
+   "dev": "vite",
+   "build": "vite build",
+   "preview": "vite preview",
+   "lint": "eslint --ext .js,.vue --fix src",
+   "test:unit": "jest",
+   "test:e2e": "cypress open"
  },
```

- **제거**: `@vue/cli-service` 및 `@vue/cli-plugin-*` 7종, `webpack`, `webpack-dev-server`, `sass-loader`
- **추가**: `vite@6`, `@vitejs/plugin-vue@5`, `vite-plugin-require-transform`, `sass@1.89` + `sass-embedded`
- lint/test는 Vue CLI 플러그인 래퍼 대신 `eslint`, `jest`, `cypress`를 직접 호출하도록 변경

### 2. 엔트리 이동 — `public/index.html` → 루트 `index.html`

Vite는 프로젝트 루트의 `index.html`을 엔트리로 사용합니다. Vue CLI의 htmlWebpackPlugin 문법을 제거하고 스크립트 엔트리를 직접 선언합니다.

```html
<body>
  <div id="app"></div>
  <script type="module" src="/src/main.js"></script>
</body>
```

### 3. `vite.config.js` — Vue CLI 호환 레이어

핵심은 **소스 코드를 최대한 건드리지 않고** 빌드 도구만 갈아타는 것이었습니다. `vue.config.js`의 설정을 옮기면서 세 가지 호환 처리를 넣었습니다.

```javascript
export default defineConfig(({ mode }) => {
  const env = loadEnv(mode, process.cwd(), '')

  // ① Vue CLI 호환: process.env.VUE_APP_* / NODE_ENV를 define으로 치환
  const processEnvDefine = {
    'process.env.NODE_ENV': JSON.stringify(
      mode === 'development' ? 'development' : mode === 'test' ? 'test' : 'production'
    ),
  }
  for (const key of Object.keys(env)) {
    if (key.startsWith('VUE_APP_')) {
      processEnvDefine[`process.env.${key}`] = JSON.stringify(env[key])
    }
  }

  return {
    plugins: [
      vue(),
      // ② require('@/assets/...') 구문 호환
      requireTransform({ fileRegex: /.(js|jsx|ts|tsx|vue)$/ }),
    ],
    resolve: {
      alias: { '@': path.resolve(__dirname, 'src') },
    },
    define: processEnvDefine,
    css: {
      preprocessorOptions: {
        scss: {
          // ③ sass modern-compiler + 전역 abstracts 자동 주입
          api: 'modern-compiler',
          additionalData: (source, filename) => {
            const normalized = filename.replace(/\\/g, '/')
            if (
              normalized.includes('/assets/scss/abstracts/') ||
              normalized.includes('/assets/scss/global.scss') ||
              source.includes('@use "@/assets/scss/abstracts"')
            ) {
              return source
            }
            return `@use "@/assets/scss/abstracts" as *;\n${source}`
          },
        },
      },
    },
    server: {
      proxy: {
        /* Vue CLI devServer.proxy 이관 */
      },
    },
  }
})
```

- **① env 호환**: Vite의 표준은 `import.meta.env.VITE_*`지만, 소스 전체가 `process.env.VUE_APP_*`을 사용하고 있어 `define`으로 빌드 타임 치환했습니다. 소스 수정 없이 동작합니다.
- **② require 호환**: webpack의 `require('@/assets/...')` 이미지 로딩 구문은 `vite-plugin-require-transform`으로 처리했습니다.
- **③ SCSS 주입**: `sass-loader`의 `additionalData`를 옮기되, `@use` 규칙은 파일 최상단에만 올 수 있으므로 abstracts 자신·이미 주입된 파일은 건너뛰는 가드를 추가했습니다.

### 4. `.env` 정리

Vue CLI 시절 `.env.*`에 있던 `NODE_ENV=...` 선언은 Vite에서 경고를 발생시키므로 제거했습니다. mode별 `NODE_ENV`는 `vite.config.js`의 `define`에서 결정합니다.

### 5. 롤백 장치

한 번에 전환하는 대신, 문제 발생 시 되돌릴 수 있게 이전 설정을 보존했습니다.

- `vue.config.js` — 삭제하지 않고 유지 (+ 롤백 안내 주석)
- `legacy/vue-cli/index.html` — 기존 `public/index.html` 백업
- `legacy/vue-cli/README.md` — 롤백 절차 문서

## 이관 후 터진 런타임 이슈

빌드는 통과했지만 webpack 환경에 암묵적으로 의존하던 코드가 브라우저에서 깨졌습니다.

### ① `global is not defined`

```
Uncaught ReferenceError: global is not defined
```

webpack은 Node의 `global`을 폴리필해 주지만 Vite는 하지 않습니다. `global.Window = ...`처럼 폴리필에 기대던 코드를 `window` 기반으로 정리했습니다.

### ② 순환 참조 — `Cannot access 'DefaultLayout' before initialization`

```
routes.js → dev-routes.js → FileListView.vue → routes.js
```

webpack의 CommonJS 변환에서는 우연히 동작하던 순환 import가, Vite의 네이티브 ESM에서는 TDZ(Temporal Dead Zone) 오류로 드러났습니다. 라우트 컴포넌트를 동적 `import()`로 바꾸고, 뷰에서 라우트 정의를 직접 import하던 부분을 `router.options.routes` 참조로 교체해 고리를 끊었습니다.

## 코드 스플리팅

Vue CLI 시절 단일 `app.js`(1.79 MiB)로 나가던 번들을 두 축으로 분리했습니다.

1. **라우트 단위**: 페이지 컴포넌트를 동적 `import()`로 전환 → 라우트별 0.3~7 kB 청크로 lazy load
2. **의존성 단위**: `manualChunks`로 대형 라이브러리를 개별 청크로 분리

```javascript
manualChunks(id) {
  if (!id.includes('node_modules')) return;

  if (id.includes('lottie-web')) return 'lottie';
  if (id.includes('swiper')) return 'swiper';
  if (id.includes('moment')) return 'moment';
  if (id.includes('axios')) return 'axios';
  if (id.includes('@tanstack')) return 'vue-query';
  if (id.includes('vue-router') || id.includes('pinia') || id.includes('/vue/')) {
    return 'vue-vendor';
  }
  return 'vendor';
}
```

\* Vite 1회차는 의존성 설치 직후 콜드 빌드입니다.

- 중앙값 기준 **19.43s → 7.57s, 약 61% 단축**
- 번들러 내부 시간 기준으로도 webpack `Time: 12544ms` → Vite `built in 5.63s`로 **약 55% 단축**

**Before** — 사실상 전부를 처음에 로드:

**After** — 라이브러리·라우트별 분리 로드:

| 청크            | 크기        | Gzip        | 로드 시점          |
| --------------- | ----------- | ----------- | ------------------ |
| `index` (메인)  | 1,541.36 kB | 1,113.11 kB | 초기               |

메인 `index` 청크가 여전히 큰 이유는 인라인된 Lottie JSON·이미지 데이터가 포함되어 있기 때문으로, gzip 압축률(72%)이 낮은 것도 같은 원인입니다. 이는 마이그레이션 이전에도 동일하게 `app.js`에 들어 있던 데이터라 회귀는 아니며, 별도 과제로 남겨두었습니다.

CSS는 `cssCodeSplit`으로 페이지별 분리되면서 전체 용량도 100.3 KB → 66.7 KB로 줄었습니다.

## 체크리스트

Vue CLI → Vite 이관 시 확인할 것들입니다.

- [ ] `public/index.html` → 루트 `index.html` 이동, `<script type="module">` 엔트리 선언
- [ ] `process.env.VUE_APP_*` 사용처 → `define` 치환 또는 `import.meta.env` 전환
- [ ] `.env.*`의 `NODE_ENV` 선언 제거
- [ ] `require()` 이미지 로딩 → `vite-plugin-require-transform` 또는 `new URL()` 전환
- [ ] `sass-loader`의 `additionalData` → `css.preprocessorOptions.scss` 이관 (`@use` 중복 주입 가드)
- [ ] `global` 등 webpack 폴리필 의존 코드 제거
- [ ] ESM 순환 참조 점검 (webpack에서는 침묵하던 오류가 드러남)
- [ ] 라우트 동적 `import()` + `manualChunks`로 코드 스플리팅
- [ ] 롤백 경로 확보 (`vue.config.js` 보존 등)
